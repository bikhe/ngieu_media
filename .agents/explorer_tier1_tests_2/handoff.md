## Logic Chain
1. Based on R1 (Optional deadline), the core capability is creating events with and without deadlines. The Tier 1 tests will cover the happy paths of event creation and modification regarding the deadline field.
2. Based on R2 (Admin attendance button), the core capability is an admin joining an event as a participant. The tests will cover the visibility of the button, the action of joining, state after joining, and capacity boundaries (normal vs. full).
3. Based on R3 (Media self-signup), the core capability is similar to R2 but for the 'MEDIA' role. The tests will cover button visibility, action of joining, post-join state, and capacity limits.
4. For Playwright setup, `npm init playwright@latest` is standard, and we will configure it specifically for the `tests/e2e` directory and typical local frontend URLs.

## Proposed E2E Tests (Tier 1)

### R1: Event Creation Optional Deadline
1. **Create Event With Deadline**: Admin creates an event providing a valid date/time in the deadline field. Verify successful creation.
2. **Create Event Without Deadline**: Admin creates an event leaving the deadline field completely empty. Verify successful creation.
3. **Edit Event - Add Deadline**: Admin edits an existing event that has no deadline, adding a valid deadline. Verify successful update.
4. **Edit Event - Remove Deadline**: Admin edits an existing event that has a deadline, clearing the deadline field. Verify successful update.
5. **Verify Default Deadline Display**: Admin creates an event without a deadline and verifies that the frontend correctly displays the 7-day default (or 'no deadline' state) on the event details page.

### R2: Admin Attendance Button
6. **Admin Join Button Visible**: Admin views an event they are not participating in. Verify the "Пойти на мероприятие" (Go to event) button is visible.
7. **Admin Joins Event**: Admin clicks the join button. Verify they are added to the participants list and the UI reflects their participation.
8. **Admin Already Joined State**: Admin views an event they have already joined. Verify the join button is absent or shows a "participating" state.
9. **Admin Joins Near Capacity**: Admin joins an event that currently has `max_participants - 1` participants. Verify successful join.
10. **Admin Join Button Full Event**: Admin views an event where current participants equals `max_participants`. Verify the join button is disabled or an error is gracefully handled.

### R3: Media Self-Signup
11. **Media Signup Button Visible**: Media user views an open event they are not participating in. Verify the signup button is visible.
12. **Media User Signs Up**: Media user clicks the signup button. Verify they are successfully added to the participants list.
13. **Media Already Joined State**: Media user views an event they have already joined. Verify the signup button is absent or shows a "participating" state.
14. **Media Signs Up Near Capacity**: Media user signs up for an event with `max_participants - 1` participants. Verify successful signup.
15. **Media Signup Button Full Event**: Media user views an event where current participants equals `max_participants`. Verify the signup button is disabled.
